DDESONN 7.3.11: Retain failed curves and clarify Iris validation errors

A first failed training attempt erased its already logged loss curve because no completed model existed. The workbench now retains loss history on failed/cancelled attempts and displays that curve with an explicit attempt/outcome label when no completed model is selected. Existing completed-model selection still controls its own chart. The retained loss remains available in the table and through hover; it is not presented as a usable model and does not enable save or prediction.

Expandable training errors now include the installed DDESONN engine and R versions. Opening newer app files from a checkout does not update the installed package used by DDESONN::ddesonn_fit(). This helps identify a possible source/installed-engine mismatch. The reported Iris failure was reproduced exactly with the historical 7.1.7 engine: validation reporting unconditionally requested binary mode for three-column multiclass probabilities. Final mode bypassed that block and returned 83.33% validation accuracy, matching the reported model. The current engine already guards that block to binary tasks. This patch adds specific reinstall/restart guidance and a regression test verifying multiclass reporting modes; training mathematics and checkpoint selection are unchanged.

Validation: 65 focused run-selection assertions passed without failures, errors, warnings or skips. An installed-app Chromium test injected a worker failure after three logged epochs and verified that the graph/table remained while no model was created. Genuine default Iris training completed for both checkpoint choices, followed by selection/mobile checks without JavaScript errors. Separate Iris runs completed all eight standardization × initial self-organization × checkpoint combinations. The final engine/R metadata probe and eight additional Iris-reporting/guidance assertions passed. No vignette build, full package check or full numerical suite was run for this patch.
