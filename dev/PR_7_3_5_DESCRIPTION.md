# Finish 7.3.5 Shiny training feedback and checkpoint controls

This 7.3.5 follow-up refines the guided Data → Features → Build & Train → Model / Results workflow released in 7.3.4, with Experiments retained separately. Training and downloads follow the state of the current browser session: Train requires prepared data and no active job, Cancel requires a job, Save requires a completed model, and new-prediction downloads require scored rows. Existing completed models remain usable while another model trains. Warm starts and model/data replacement wait for the current job to finish or be cancelled.

New fits default to the best validation checkpoint (classification accuracy or regression MSE), restoring both weights and biases before inference; final-epoch weights remain an explicit alternative. Both choices run all requested epochs. Summaries identify the selected epoch, fit budget, selection mode, criterion and validation score. Initial self-organization runs only for new models. Equivalent R panels and downloaded recipes retain the completed model's choices and append warm starts without repeating initial self-organization.

Training failures offer actionable guidance and expandable worker diagnostics. Failed and cancelled jobs retain the previous completed model. Loss-chart hover reports epoch and loss without selecting weights; an expandable table supports keyboards and touch screens. Small lowercase-i help controls and right-aligned switches remain keyboard accessible.

Validation: 72 tests and 12,580 assertions passed with no failures, errors, warnings or skips. Installed-app desktop/mobile checks cover both checkpoint choices, training, cancellation, model persistence, prediction, warm starts, session isolation and keyboard/touch controls. Downloaded best, final and warm-start recipes reproduce their models. The pre-bump normal package build rendered all four vignettes. Before the version bump, full `R CMD check` of the same runtime code passed with `Status: OK`, including vignette rebuilding and the PDF manual, using `R_RD4PDF=times,hyper` for the installed Times/Courier fonts. The default font configuration produces one environment warning because `inconsolata.sty` is missing. The original validation evidence remains in `dev/workbench-7.3.4-validation.md`; the 7.3.5 metadata and historical release audit are recorded separately. This is version 7.3.5. No optimizer implementations, automatic early stopping, release tags, merges or publication are part of this change.

A pre-existing single-predictor core preprocessing error remains. The workbench now explains the shape failure and preserves the prior model; two or more numeric predictors are the verified workaround.

The release-description audit covers every tag from v7.1.1 through v7.3.4 and records eight historical tag/package-version mismatches without rewriting tags. NEWS preserves the actual 7.3.4 release section and puts the follow-up features under 7.3.5. See `dev/release-description-audit.md`.
